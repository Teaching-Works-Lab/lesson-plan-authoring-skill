# Knowledge Map Contract

## Purpose

The map is a compressed model of lesson knowledge, not a schedule, workflow, or assessment chain.

## Shape

Use:

`lesson topic → 2–4 first-level modules → specific concepts / mechanisms / relationships`

First-level siblings should be conceptually parallel. Second-level nodes should be concrete enough to teach or test.

## Exclude

Do not include:

- unit IDs or assessment IDs;
- “可运行代码 / 学习证据 / 提交报告 / 后续课次”;
- teacher/student activity labels;
- generic arrows that merely show progress;
- unrelated template nodes inherited from another course.

## Visual checks

- title fully visible;
- hierarchy readable at Word page scale;
- no clipped C++ symbols, Chinese glyphs, or long headings;
- same visual grammar across the course, while content differs by lesson.
